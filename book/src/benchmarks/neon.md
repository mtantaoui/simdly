# NEON

Speed-up of simdly's NEON backend (4 `f32` / 2 `f64` lanes) over the scalar loop; see
[Methodology](./README.md).

| Machine  |   |
|----------|---|
| CPU      | Apple M4 (MacBook, 16 GB) |
| Threads  | 10 |
| OS       | macOS |
| Rust     | – |
| simdly   | – |

The compiler vectorises the scalar loop of the cheap operations (`add`,
`abs`, `ceil`, `sqrt`, …) itself, so those stay near 1×. This run was made
without `--features rayon`.

## Parallel

`ParSliceExt` and `ParSliceMath` (feature `rayon`) on every thread of the
machine, from the `par` and `rayon` results of the same groups; see
[Parallelism](../parallel.md). Up to the threshold (262 144 elements for
math, 524 288 for arithmetic and comparisons) `par_` runs on one thread,
so "over one thread" is about 1× there.
